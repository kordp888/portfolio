# 공고 요구와 경험 근거 비교 · 고용24 공모전 기획안

작성 2026-10-15, 제출안 원문 대조와 검증 패키지 실행으로 수정 2026-10-16. 근거는 제출 PDF(A4 8쪽, 2026-10-13 개인 참가), 별도 준비 저장소의 규정·자료 검수 기록, 합성 검증 패키지입니다. 평가용 공고와 정답 내용은 싣지 않습니다. 제출 PDF와 제출 기록은 수정하지 않았습니다.

## 상태

2026-10-13 기획안을 제출했습니다. 접수는 본인이 확인했고 접수증 사본은 이 저장소에 없습니다. 선정과 수상은 정해지지 않았습니다. 제출 단계는 기획 제안이며 실제 API 연동, 동작하는 서비스, 모델 성능 평가는 아직 없습니다.

공모요강 기준 일정은 개발 10/23~11/5, 기능 심사·공개 검증 11/10~19, 본선 발표·시상 11/27입니다(2026-10-15 조회, 10-16 재확인, 변경 공지 없음). 기존 코드를 어디까지 쓸 수 있는지, 개발 기간 전 작성한 코드가 제출물에 포함될 수 있는지는 명시된 답을 찾지 못했습니다. 금지나 허용으로 단정하지 않고, 제출용 신규 기능 개발은 보류했습니다.

## 문제

공고의 지원 조건을 확인하는 일과, 수행한 프로젝트가 어떤 직무 역량을 보여 주는지 설명하는 일은 서로 다른 과제입니다. 출발점은 참가자가 제시한 "학력과 실제역량" 사이의 간극입니다. 학력 정보만으로 드러나지 않는 수행 경험을 공고의 업무 언어로 설명하되, 학력·자격·경력의 필수조건은 그대로 남겨 두는 것이 목표입니다. 문제의 발생 빈도는 아직 검증하지 않았습니다.

## 대상 사용자

AI 서비스 구현과 고객 문제 해결에 관심 있는 FDE 및 유사 AI 직무 준비자입니다. 공고마다 직무명이 달라 첫 평가는 한 직무군의 공고만 다룹니다.

## 내 역할

개인 참가입니다. 문제 제기, 최종 설계 선택, 문서 내용 검토를 맡았습니다. 공개자료 조사, 설계 선택지 정리, 문서 초안과 합성 예시 작성은 AI가 보조했고 제출안에도 그렇게 적었습니다. 이 사례에서 신규 제품 코드를 직접 구현했다고 쓰지 않습니다.

## 설계 선택과 대안

| 선택 | 버린 대안 | 이유 (제출안 근거) |
|---|---|---|
| 요구 단위로 인용과 근거를 붙인다 | 공고 전체를 적합도 점수 하나로 축약 | 점수로 줄이면 어떤 조건이 확인됐고 무엇이 빠졌는지 알기 어렵다 |
| AI는 요구 분리와 경험 후보 연결만, 명시조건과 인용은 규칙 검사 | 의미 유사도로 자격 충족까지 판정 | 표현이 다른 수행 문장 연결에는 문맥 해석이 필요하지만, 비슷하다는 이유로 자격 충족을 확정하면 안 된다 |
| 학력 미기재는 확인 필요로 보류 | 미기재를 미충족으로 처리 | 입력 근거가 없다는 사실을 역량이 없다는 판정으로 바꾸지 않는다 |
| 합성 공고·합성 경험 카드만 선택 | 실제 이력서 업로드, 외부 증빙 링크 | 개인정보와 검증 범위를 시연 단계에서 제한한다 |

첫 버전에서 하지 않는 일은 지원자 선별·순위화, 합격확률, 능력 총점, 자동지원, 여러 공고 추천, 자기소개서 자동완성입니다.

## 상태 4종

상태는 사람의 능력이 아니라 각 요구에 연결된 입력 근거의 상태입니다.

| 상태 | 적용 기준 |
|---|---|
| 근거상 연결됨 | 관련 수행 문장과 해당 요구의 모든 명시조건에 입력 근거가 있음. 미확인 필수조건이 있으면 쓰지 않음 |
| 부분 근거 | 복합 요구 중 일부에만 근거가 있음. 남은 요소를 함께 표시 |
| 확인 필요 | 입력 누락, 모호한 표현, 인용 오류, 조건 충돌로 보류 |
| 입력상 명시조건 미충족 | 분명한 필수조건과 이를 충족하지 못한다는 명시적 입력이 함께 있을 때만 |

"학사 이상 필수"와 "최종학력 고졸"이 함께 있으면 명시조건 미충족입니다. 이때도 다른 업무 역량에 연결된 경험은 지우지 않습니다. 학력 우대를 지원 자격으로 바꾸지 않고, 학습·개인 프로젝트를 유급 경력으로 환산하지 않고, 겹치는 기간을 중복 합산하지 않습니다.

## 데이터와 처리 흐름 (설계)

입력 선택, 요구 분리(필수·우대·업무·불명확), 근거 연결, 비교 검토, 정정과 보완의 5단계입니다. 처리는 요구 추출, 후보 연결, 구조·인용 검사, 명시조건 검사, 표시 또는 보류 순서입니다. 시연 데이터는 고용24 채용정보 공개 API 명세의 구조를 참고한 완전 합성 공고와 자체 합성 경험이며 실제 API 응답 확보나 연동을 주장하지 않습니다. 모델과 호스팅은 미정입니다.

## 실패 대응 (설계)

충돌이나 검사 실패는 확인 필요로 보류하고, 재시도 뒤에도 자동 충족으로 메우지 않습니다. 공고·경험 안의 지시문은 데이터로 다루고 모델에 링크 방문·파일 실행·도구 호출 권한을 주지 않습니다. 모델 장애 때 저장된 예시를 보여 줄 수는 있지만 실시간 결과로 표시하지 않습니다. 모두 구현 전 설계입니다.
