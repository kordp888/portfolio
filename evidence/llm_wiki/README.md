# LLM Wiki: 가산 전용 동기화 Evidence Pack

운영 지식 파일 삭제 사고 뒤에 동기화 계약을 어떻게 바꿨는지 보여 주는 공개 합성
하네스입니다. 프로덕션 소스, 위키 내용, 운영 로그를 포함하지 않습니다.

## Observed

2026년 7월 동기화 사고로 운영 지식 파일 171개가 삭제됐고, 복구를 마쳤습니다.
삭제를 일으킨 옛 미러의 정확한 구현과 실행 경로는 확인되지 않았습니다.

관측된 사실은 파일 삭제와 복구입니다. 아래 실패 추적은 원래 사고 로그가 아닙니다.

## Reconstructed

[정본 합성 입력](./input.canonical.synthetic.json)은 항목 A, B, C를 가지고 있습니다.
[모바일 합성 입력](./input.mobile.synthetic.json)은 A를 체크하고 B를 해제하며 C를
누락하고, 정본에 없는 D를 추가합니다.

양방향 동기화가 모바일 상태를 정본으로 그대로 해석하면 세 위험이 생깁니다.

- B의 기존 체크가 해제될 수 있습니다.
- 모바일에서 보이지 않는 C가 삭제될 수 있습니다.
- 정본에 없는 D가 삽입될 수 있습니다.

[재구성된 실패 추적](./trace.fail-reconstructed.json)은 이 위험을 설명하기 위한 합성
자료입니다. 옛 구현을 복원하거나 원래 사고 원인을 입증하지 않습니다.

## Verified

[공개 하네스](./additive_sync.py)는 모바일 변경에서 체크 추가만 받습니다.

| 입력 상태 | 판정 |
|---|---|
| 정본이 미체크, 모바일이 체크 | 정본을 체크로 변경 |
| 정본이 체크, 모바일이 미체크 | 정본 체크 유지 |
| 모바일에서 정본 항목이 누락 | 정본 항목 유지 |
| 모바일에 미확인 항목이 추가 | 정본에 삽입하지 않고 `unmatched`로 기록 |
| 모바일 행 순서가 변경 | 합성 ID로 찾아 같은 결과 생성 |

[통과 결과](./expected.after.json)는 항목 수와 순서를 그대로 유지합니다.
[통과 추적](./trace.pass.json)에는 `removed=[]`, `unchecked=[]`가 기록됩니다.
[익명 합성 로그](./log.anonymized.txt)는 실제 시각 대신 상대 시각과 합성 ID만
사용합니다.

## 검증

```bash
python3 -m unittest evidence.llm_wiki.test_additive_sync
```

공개 테스트는 체크 추가, 해제 방지, 삭제 방지, 미확인 항목 차단, 순서 독립성,
멱등성, 입력 불변성, 공개 파일과 하네스 결과의 일치를 검사합니다.

최근 결과는 [verification.txt](./verification.txt)에 있습니다.

## 공개 범위와 한계

- 모든 입력과 추적은 합성 자료입니다.
- 실제 위키 문장, 기사, 링크, 사용자 정보, 기기 정보는 없습니다.
- 공개 하네스는 프로덕션 소스의 복사본이 아닙니다.
- 옛 동기화 구현의 정확한 삭제 경로는 재현하지 않습니다.
- 이 사례가 모든 종류의 파일 손실을 막는다고 주장하지 않습니다.
